# Kuvion — продакшен-сборка (GitHub Pages)

Демо-прототип интерфейса: фильмы, сериалы, аниме и манга в одном месте.
Сборка сгенерирована скриптом `scripts/build_prod.py` из однофайловых
черновиков (папка `download/` проекта) — **правки вносятся в черновики,
затем сборка повторяется**.

## Структура

```
/                      главная
/catalog/              каталог (фильмы, сериалы, аниме; ?type=, ?random=1)
/title/                страница тайтла («Атака титанов»; ?cmt= — якорь комментария)
/manga/                манга (?m= — глубокая ссылка на тайтл, ?ch= — глава)
/mylist/               мой список
/collections/          подборки (?c= — глубокая ссылка на подборку)
/collections/new/      создание/редактирование подборки (?edit=)
/schedule/             расписание выхода серий
/search/               страница результатов поиска (?q=)
/notifications/        уведомления
/person/               персона (?mode=seiyuu|people)
/profile/              профиль
/settings/             настройки
/plus/                 Kuvion+
/404.html              страница «не найдено» (GitHub Pages отдаёт её автоматически)
/assets/               общий слой дизайн-системы:
  kuvion-common.css    CSS, общий всем страницам (кэшируется между переходами)
  kuvion-search.js     движок поиска v3.4 (единый индекс: тайтлы + персоны + подборки)
  kuvion-auth.js       авторизация v3 (вход + регистрация в 3 шага)
  kuvion-data.js       СЛОЙ ДАННЫХ: демо-база всего сайта + адаптер KuvionData
  favicon.svg          исходник фавиконки (в страницах — inline data-URI)
```

## Слой данных kuvion-data (главное изменение сборки)

Все демо-данные сайта вынесены из страниц в один файл `/assets/kuvion-data.js`:

- **`KuvionData.page('home'|'catalog'|'title'|…)`** — страница читает своё
  пространство демо-данных (статусы, вселенные тайтлов, hero, персоны,
  подборки). В черновиках тот же слой идёт inline-блоком KVUION-DATA,
  в проде — общий файл, кэшируется между переходами.
- **`KuvionData.api.home()` и др.** — контракт будущего API: каждый метод
  возвращает Promise со снимком «своего» пространства. Когда появится
  бэкенд, тела методов заменяются на `fetch('/api/…')` — и весь сайт
  переезжает на реальные данные правкой одного файла. Структура ответа
  каждого метода = структура соответствующего пространства демо-базы
  (см. шапку `kuvion-data.js`).
- Одинаковые пространства — алиасы (`_db.notifs=_db.home`): страницы
  «уведомления», «поиск» и Kuvion+ делят вселенную главной, шесть
  страниц — вселенную каталога.
- Источник данных — единая база `scripts/kuvion-data/db.js` в проекте
  (сборка: `assemble_db.py` → `emit.js` → `patch.py` → `build_prod.py`).
  В репозитории сайта её «слепок» лежит в `data/payloads/` — см. ниже.

### Обновление демо-данных без пересборки страниц вручную

В репозитории лежит самодостаточный `data/patch_site.py`: он собирает
`/assets/kuvion-data.js` из `data/core.js` + `data/payloads/*.js` и
вшивает слой в страницы. Достаточно обновить payload-файл и запустить
скрипт (локально или GitHub Actions):

```
python3 data/patch_site.py --root .
```

## Деплой

Сайт — статика, сервер не нужен.

- **Пользовательский сайт** (`username.github.io`) или **кастомный домен**:
  содержимое этой папки — в корень репозитория. Ссылки корневые (`/catalog/`).
- **Проектный сайт** (`username.github.io/<имя-репо>/`): пересобрать с базой —
  `python3 scripts/build_prod.py --base /<имя-репо>` — и коммитить результат.

## Как дорабатывать

1. Поправить черновик в `download/` (например `kuvion-draft-v4.html` — главная,
   `kuvion-title-v2.html` — страница тайтла; «Лаборатория» в черновиках —
   панель быстрого просмотра состояний, в продакшен она не попадает).
2. Пересобрать: `python3 scripts/build_prod.py` (из корня проекта).
3. Проверить: `node scripts/test_prod.js` — структура, паритет стилей с
   черновиками (1280/1024/390 px) и функциональные потоки;
   `node scripts/test_data_layer.js` — слой данных (черновики и прод).
4. Закоммитить `download/kuvion-prod/` и запушить.

Однофайловые черновики в `download/` остаются эталоном дизайн-системы:
каждый открывается локально двойным кликом и содержит всё в одном файле
(включая inline-слой данных — страницы работают автономно).

## Демо-данные

Все постеры, списки, комментарии и события — тестовые (CDN-картинки,
localStorage, демо-база kuvion-data.js). Демо-режим по умолчанию —
«пользователь»: чтобы увидеть состояние гостя — меню аккаунта → «Выйти»;
вход — любые email и пароль. Промо-коды и «Потому что вы смотрели» —
запланированные фичи.
